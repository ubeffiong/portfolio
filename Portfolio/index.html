DAVT: Data Analytics and Visualization Tool (SECURE-Nigeria)

Architect / Technical Lead · IHVN & NCDC
Deployed

NCDC's surveillance analytics layer, which turns SORMAS and other data into dashboards, the Weekly Epidemiological Report, alerts and decisions. It has been used in all 36 states and the FCT since January 2024.

  • 6 → 37 states + FCT
  • 10 analysis modules
  • 5 connected data sources
  • 5–6 wks → real time weekly report
Read the full case studyClose case study
The problem

Surveillance data was collected but hard to turn into evidence. Reports were compiled by hand and late, there was no single outbreak view, decisions were recorded manually, and there was no automatic cross-check of SORMAS against other sources.

Objectives
  • Integrate surveillance sources and reliably extract and transform records.
  • Provide interactive dashboards and trend analysis by place and time.
  • Make routine reporting efficient and consistent.
  • Strengthen traceability with audit trails and controlled access.
  • Build an extensible base for advanced statistics and prediction.
What was built
  • Standalone SORMAS data-pull service that separates ingestion from the dashboards.
  • Dashboards & analytics: summary, aggregate and case-based views, geospatial and temporal analysis, and a live EOC wallboard.
  • Weekly Epidemiological Report generated from live data.
  • Threshold alerts and a decision tracker from alert to resolution.
  • Triangulation: SORMAS, IDSR-002, state line lists, DHIS2 (NPHCDA) and MedSafety (NAFDAC).
  • Audit trail recording system activity for accountability.
Data engineering

Extraction schedules, pagination, schema compatibility, failed requests, duplicate prevention, separating missing values from zero counts, and traceability from results back to source records.

Next: built & specified
  • Built Digital WER workflow, automatic situation reports, the National IDSR Compliance Index and advanced analytics, awaiting NCDC adoption.
  • Specified DAVT Analytics Studio: hybrid R/Python execution, row-level access by default, multi-level geography, time-series, spatiotemporal and regression analysis, and reproducible exports for high-volume data.
  • .NET
  • JavaScript
  • SQL

  • SORMAS API

Bioinformatics Analyst & Developer · Creator

  • 4 reconstruction tools benchmarked

Read the full case studyClose case study
Why it matters

Plasmids can carry resistance genes between bacteria. Finding the same gene in two isolates does not prove transmission. That needs plasmid similarity, genomic context, bacterial relatedness, metadata and careful interpretation.

The three tools
  • PlasBench: benchmarks MOB-recon, Platon, plasmidSPAdes and gplas against truth sets (precision, recall, F1, failure modes). GitHub
  • PlasmiCord: pairwise plasmid distances, clustering and isolate-sharing networks to find candidate horizontal spread. GitHub
  • PlasmidTrace: links reconstruction reliability with sharing evidence to produce confidence scores; needs external validation.
Shared pipeline
  1. Sequencing data & metadata (FASTQ, FASTA, assemblies)
  2. QC & genome processing
  3. Annotation & resistance profiling (Prokka, ResFinder, CARD)
  4. Plasmid comparison, clustering & phylogeny
  5. Evidence-based interpretation & reproducible reports
Research quality

Records software and database versions, parameters, input checksums, QC metrics and output provenance. Keeps observed data separate from inferred relationships, documents uncertainty, and never treats a database match as proof of resistance or transmission.

The problem

Clinical data is only as good as its codes. Teams code by hand across ICD, LOINC, RxNorm and SNOMED CT with no shared validation, no audit of why a code was chosen, and no safe way to manage local codes or mappings.

What CODA does
  • Search, look up, validate and explain codes across terminologies, served live from their publishers (WHO ICD-11, LOINC, RxNorm and other UMLS sources) under each organisation's licences.
  • Every selection and review is recorded as an audited decision.
  • Local dictionaries and mappings with four-eyes review, plus value sets.
  • An AI phrase assistant that suggests candidates; deterministic rules decide.
  • An EMR sandbox and embeddable components to drop terminology search into any clinical app.
Architecture & engineering
  • API: .NET 10 modular monolith, PostgreSQL, OIDC/JWT (authorisation code + PKCE), role-based access and a full audit trail.
  • Web: React + TypeScript coding workbench and reusable components.
  • Resilience: a local copy of every terminology, refreshed monthly, answers when a live source is down.
  • Interoperability: FHIR adapter; SNOMED CT through an evaluated terminology engine.
  • Quality: CI with build, tests, vulnerability scans, Playwright end-to-end journeys, load tests and observability.
SDKs for integrators

Thin, dependency-light clients with one shared contract in C#/.NET, TypeScript/JavaScript, Python, Java, Go and Rust, released with verified checksums.
